## 一、我自己造的，已全部修完（8 条）

### ① 我 r18 的完结修复其实是个 3 周定时器

`_cannot_have_aired_all` 问的是「这一季播完了没有」，而答案会随时间变成「播完了」。
真库实测：anime#6 的闸 **2026-09-20** 到期、#60 是 **09-21**，之后同一份假 coverage
会把两部重新判成完结，**而让 coverage 变假的那批种子一条都没动**。

补了一条不看时间、只看分布的判据：超出总集数的集号有 ≥3 个、同时 1..T 里也有货 → 不判完结。

**阈值 3 有实证，不是拍脑袋**：真库里有超界集号的 5 部，超界集数是 **21 / 8 / 8 / 7 / 3**，全部 ≥ 3；
而项目自己那条 `test_extra_episodes_beyond_total_are_fine` 要保护的场景（bgm 少记一集）是 **1**。
**1~2 这一段在真库上是空的**——那道缝就是阈值的位置。
验证方式：把时间闸打桩成「已经播完」，两部番仍然判不出完结。

## 二、不是我造的（已修 4 条 / 待拍板 4 条）

### 已修

- **`get_text` 的 charset 守卫只接 `LookupError`**。它盖住的是「编码名不存在」和「二进制编解码器」，
  而还有一类是**存在、也是文本编码、但拒绝 `errors='replace'`**：`idna` 抛 `UnicodeError`、
  `punycode` 抛 `UnicodeDecodeError`。两者都能从这里逃出去打断整轮采集。
  原用例喂的编码名**正好只覆盖会抛 `LookupError` 的那一半**——"用例只测了自己传进去的那一类"。
- **`load_from_db` 的补键循环没有并发保护**。它和紧随其后的 `_merge_new_notify_events` 面对
  同一个 UNIQUE 风险，而**只有后者被整段兜住**（第①种缺陷形状）。触发窗口就是那段注释自己列的
  「升级后第一次启动」叠上两个进程同时起。改成幂等写 + 撞了重跑一次。
- **`loaded_from_db` 这道闸只装在设置页的 `_save` 里**，而全站还有**三个**同样"把表单值写回配置"的
  处理器一个都没过闸：『应用开始使用日过滤』（会把开始使用日覆盖成空、把全部超期忽略的番放回待确认，
  然后弹一条**绿色**的成功提示）、/movies 的『保存自动扫描设置』、/parse 的多括号开关。
  闸抽进 `layout.require_config_loaded()`，加 AST 守卫 + 一份带理由的豁免名单
  （`_switch_backend` 写的是字面量，且它正是库出问题时的自救出口，拦掉反而把人关在门外）。
- **『季度显示』框渲染的是派生值**。`config.QUARTER_FMT_UI` 走 `__getattr__` 返回
  `_v["QUARTER_FMT_UI"] or _v["QUARTER_FMT"]`，而保存链路原样把框里的值写回原始键——
  **读派生、写原始，一次保存就把「留空＝跟随」塌缩成「钉死在当时那个字面量」**。
  加了 `config.raw()` 取原始值。⚠️ **这件事在真库上已经发生过**：raw 值现在是 `{yy}{q}` 而不是空串。
- **`.env` 每次保存都重写**，且成功提示恒带「（Web 绑定地址/端口改动需重启）」——
  表单收的是全量而不是差量，那个三元的 else 分支永远走不到。改成只收真的变了的项。

## 三、审计确认「攻了没攻破」的部分（同样有价值）

- **无代理口径的 SSRF 守卫是硬的**：DNS 重绑定（TTL=0 交替应答）实测 `getaddrinfo` 只被调用 1 次、
  钉 IP 真的在起作用；`[::1]` / `[::ffff:7f00:1]` / `127.1` / `[64:ff9b::7f00:1]` / 带 userinfo /
  十进制写法逐条实测全拦。
- **`/api/qb/done` 没攻破**：10 组请求（XFF / Origin / Sec-Fetch-Site / 非环回源 IP / GET）全拒。
  `proxy_headers=False` 的契约成立且线上生效——从 127.0.0.1 带 `X-Forwarded-For` 打，
  回的是「behind a reverse proxy」而不是「non-local address」，说明 `scope['client']` 没被改写。
- **bencode 解析器没打穿**：11 组畸形输入（10 万层嵌套、5 百万层 list、100 万位整数、负长度、
  超大声明长度）全部返回 None，最慢 36ms、峰值 0.4MB。
- **密钥脱敏的生产路径干净**：六种失败场景走一遍，NOTIFY_URL 的路径密钥与 feed token 一个都没落进日志；
  全仓 6 处 `log.exception`/`exc_info=True` 逐处追下去没有一处的异常来源带得上它们。
- **feedparser 侧**：XXE 不展开、外部 DTD 不抓取、十亿笑被 expat 自带的放大保护封住。
- **AnimeAlias 归一化没有互相污染**：168 条别名 `(title, season)` 无重复，
  NFKC + 去标点后唯一一对同名是 Re:Zero 的 #98/#100，而两者季号不同。
- **配置往返**：66 个键逐个「存进去再读出来」，只有 5 个不等值，其中 4 个是设计意图
  （三个密码的「留空=不改」、qB 探活失败自动关开关），1 个是上面那条 `QUARTER_FMT_UI`。

## 四、识别链的准确率（真库实测）

| 口径 | 数字 |
|---|---|
| 已有绑定的正确率 | **96 / 98 = 98.0%**（错的两部是 #86、#100，都是已知案例） |
| 98 部的 bgm 元数据与今天线上值的一致性 | **0 处漂移** |
| 把自动路径在今天重跑一遍（每部番的首条种子 + 真 bgm 网络） | 绑上 94 部、**错 4 部（4.3%）**、给不出答案 5 部 |
| 既绑上又绑对 | **90 / 99 = 90.9%** |

**主要失败模式**（按真库份额排序）：
1. **集数倒推首播日**（`_date_ok`）：续季/多 cour 的种子写绝对集号，`est = release-(ep-1)周`
   必然指到上一季的首播窗口，于是正确 subject 被日期闸判否、同系列的另一部被判对。
   #86 / #60 / #6 / #100 **全是这一条**。
2. **名字校验只要一个 2-gram 重合**（`_name_not_contradicted`）：「北斗」两个字就够。
   与第 1 条叠加（长番 ep>30 时日期校验整体关闭）就是无声误绑。
3. 单票即绑 + bgm 上特典与正片同名（#96）。
4. bgm 搜索召回不足（繁体名/罗马音搜不到）。
5. 特別篇被当成正片第 1 集（#95，唯一未识别的一部）。

第 1、2 条合起来就是 **E-42**；第 5 条是 **E-43**。
