## 一、修掉的问题（按严重度）

### P1 · qB 同步：被采样到中间态的种子永远落不了定

`_sync_qb_status` 把补查名单与在下名单拼成 `rows_all`，再用 `if tid in recheck_ids: continue`
跳过补查行 —— 但两个名单**不互斥**：`_QB_TRANSIENT` 的 7 个态
（checkingDL / allocating / metaDL / forcedMetaDL / checkingResumeData / moving / checkingUP）
带 T 不带 X，`progress<1` 时两边同时命中，而那句判断按 tid 走、认不出手上这份来自哪一半。

后果三重：恒满足 in-flight（同步循环永不休眠）；`sent ∈ HAVE_STATUSES` 让集去重认定这一集
"已有一份"而盘上什么都没有（**该集永久漏投、零告警**）；归档与 `qb_summary` 都排除它，永远挂在『下载中』。

触发条件很日常：qB 重启让所有未完成种子经过 checkingResumeData/checkingDL，
开着预分配时每个新种子经过 allocating，磁链交付经过 metaDL。
**7 个态全部独立复现过**（4 轮同步之后仍是 `sent`）。

修法：新增 `_recheck_where()`，末尾用一个 `or_` 把"NOT in-flight"写进 SQL，两条 WHERE 严格互斥。
**没有**改成"给这 7 个态补上 X"——那会把它们踢出 `_inflight_where`，而 recheck 查询带着搭车条件，
在下的只剩这一条时就彻底没人问了（`checkingUP` 当初从 `SX` 改成 `ST` 正是为了躲开它）。

### P1 · 停滞检测在默认配置下从未生效过

`_observation_gap` 的窗口取 `max(600, QB_SYNC_INTERVAL*10)` —— 按**活跃**节拍（30s）算。
但真正决定"两次同步隔多久"的是 `run_qb_sync` 的**中档**节拍：无源 0 速的种子让
`has_active_downloading()` 恒 False，内层快循环跑满 `QB_SLOW_ROUNDS` 就退出，
外层睡 `QB_IDLE_RECHECK_MIN*60` = **600 秒**，恰好等于那个窗口。
于是每次唤醒的第一轮都被判成"观测断档"、把 `qb_progress_at` 重置回 now；
同一突发内后两轮只隔 30 秒，`now - qb_progress_at` 最大 90 秒 ——
离 `QB_STALL_TIMEOUT_MIN`（默认 1440 分钟）差三个数量级。

**判据用错了节拍。** 用例复现：跑满 26.7 小时零推进仍不触发。
修法：窗口改成 `max(600, QB_SYNC_INTERVAL*10, QB_IDLE_RECHECK_MIN*60 + 300)`，
并补一条"窗口必须严格大于最慢的正常节拍"的判据守卫（挡"以后改了默认值忘了窗口"）。
另一半（真正的关机/qB 挂掉仍不能算到种子头上）用反向用例钉住。

### P1 · 整库维护与业务写入之间没有互斥闸

两条独立发现指向同一个缺口，都端到端复现过：

1. **切库不看在途交付**。交付协程进锁置 `downloading` → `await` 取种（最长 180 秒）+ 加 qB →
   按**整数主键**回写。而 `db/transfer.py` 明确保留主键 —— 两个库里 id=501 是两条毫不相干的种子。
   用户在这 180 秒里点『切到 MySQL』，回写就落进另一个库的另一行：
   那一集被静默标成"已交付"（集去重从此永远挡着），而盘上什么都没有。
2. **迁移只锁住了采集与剧场版扫描两条后台线**。页面上的写入口（补齐该源 / 新增源组 / 绑定 bgm）
   完全不受约束。迁移是"先 DELETE 清空目标 → 按 500 行一批**显式带 id** INSERT"，
   中途一条并发插入就撞 `IntegrityError: UNIQUE constraint failed: animetorrent.id`，
   目标库停在"清空 + 写了一半"（1200 行的源，目标只剩 501 行）。

修法是**一个节流点**，不是逐处加闸：

- `db.maintenance(reason, blocked_by=...)`：期间 `get_session()` 一律抛 `DatabaseBusy`。
  全仓 316 处业务库访问**全部**走它，而 `db/transfer.py` / `db/schema.py` / `db/backup.py`
  用的是显式引擎、一处都不走它 —— 这一个点既拦得住全部业务读写，又拦不到维护自己。
- 维护并进 `is_data_down()`：后台四条循环的把门判据只此一条，一次覆盖全部后台线。
- `blocked_by` 收在 `maintenance()` **里面**而不是调用方：调用方"先查一遍再进维护"的写法，
  中间隔着一个 `await confirm(...)`（用户点确认要几秒到几分钟），窗口大得能开进一整轮交付。
  放在里面，检查与置位之间没有 await。
- 页面把"维护中"与"连不上"分开显示 —— 把一次几秒的、用户自己点出来的维护说成
  "系统已停摆…恢复后 30 秒内自动接上"是纯粹的误导。

### P1 · 无 Host 头校验 → DNS 重绑定可完全接管这个无鉴权面板

攻击者把 `rebind.evil.tld` 的 A 记录 TTL 设成 1 秒，先解析到自己的服务器，
诱导受害者打开 `http://rebind.evil.tld:2333/`（端口是本项目公开的默认值），页面 JS 轮询 `fetch('/')`；
随后把 DNS 改答 127.0.0.1（或面板所在的局域网 IP）。重绑定完成后**浏览器认为该来源与面板同源**：
JS 能读页面 HTML、取 NiceGUI 的 client id、连 `/_nicegui_ws/socket.io/`，像用户本人一样驱动整个 UI ——
而设置页上渲染着 qB 的地址与账号密码，下载目录也能改。

两道现有防线都不生效：`SubnetGuard` 看到的对端就是受害者本机（127.0.0.1 恒放行）或白名单网段内的 IP；
`WEB_HOST=127.0.0.1` 也不设防（请求确实来自本机）。

修法：`core/netguard.host_allowed()` —— 浏览器不允许脚本伪造 Host。
放行字面 IP / localhost / `.local`·`.lan`·`.internal`·`.home.arpa` / 用户在
新配置键 `WEB_ALLOW_HOSTS` 里列出的域名，其余 403。
**不会把人锁在外面**：按 IP 访问永远放行，403 的正文里直接写着这条自救路径。
HTTP 与 WebSocket 两条都挡（重绑定之后攻击页面真正要连的是 socket.io）。

### P1 · E-18 只做了番剧侧，`enrich_movie` 仍会静默删掉另一部片整行

R20 把番剧侧的识别路径收口成"不合并、只记日志 + 推通知"，`core/movies.py` 原样保留了 `_merge_movie`。

⚠️ 这里有个容易搞混的地方，写清楚免得下一轮又来回改：R20 曾**回退过** `_upsert_movie`
那一处的同款改动，理由是"那里的 keeper 是按 bgm_id 查出来的、合并是构造上正确的"。
**那个判断对 `_upsert_movie` 成立，但 `enrich_movie` 不是那条路** ——
它的 bgm_id 来自一次全新的 `enrich.resolve`，两行"是同一部"从没被证明过。
剧场版的续作/重制/总集编彼此极像，而"上架日当首映日"的日期校验对它们系统性地判错。

### P1 · 剧场版季度点选是全站唯一没被 token 表管住的按钮颜色

`outline color=blue-grey` → Quasar 渲染成 `.text-blue-grey`，而 `quasar.important.prod.css` 里那条是
`color:#607d8b!important`。在卡片底 `#1d1d1d` 上对比度 **3.86:1**（低于 4.5:1 的可读下限），
而站里其余中性按钮走的 `.q-btn.text-grey`（已重映射成 gray-400）是 6.48:1。
改成 `outline color=grey` + `.btn-sm`（跟同行控件走），两档都登记进角色词表。

### P1 · 『立刻刷新』在 qB 关机时弹绿字「没有正在下载的种子」

`sync_qb_status` 用 `0` 同时表示三件事：真没在下 / qB 连不上 / await 期间关了跟踪。
而整条链（`_login` 的 `except httpx.HTTPError → None` → `torrents_info` 的
`if resp is None: return None` → `if info is None: return 0`）**从头到尾不抛异常**，
页面那句 `except Exception → 同步失败` 恰恰接不住它注释里点名的那一种。
两个验证视角各自用真实故障路径复现：qB 关机时弹绿字，而同屏正写着『正在下载（5）』。

改成三态（`int | None`），与本项目已有的 `add_to_qb` / `download_*_torrent` 同形；两个页面各自分开说。
