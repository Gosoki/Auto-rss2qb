## 二、逐组落地（方案细节见代码注释与 DECISIONS）

### 2.1 要拍板的 5 项，我的决定
1. **补齐开播前余量 30 天**：保持。另外，自动补齐遇到没有发布时间的结果一律不收（DEC1x）：判断不了是不是本季的，就不让它直接下。
2. **锁定源落后自动兜底**：做（E-74）。为什么要加"兜底标记列 + 锁定组补发后再下它的版本"：created_at 时钟重放的误触发约 11%，有了这一步，误判的代价就只是多一份。
3. **已删除语义**：定为"这一集不要了"（E-73）。新增 `ep_dropped` 列，只在删最后一份时置位。不直接把"已删除"并进已有，原因是生产上 7 条里有 5 条是删重复份，朴素做法会把留下的那份挡死。
4. **单部作品默认自动下**：保持。另外补了"像剧场版的先进待确认"（已提交）。
5. **剧场版自动化**：只做"入库不下载"那部分：往前刷新版本、扫描失败退避、`bgm_down` 判据、识别改为候选回显确认、年份锁。推荐标签、"新版本"标记、自动下载都没做。

### 2.2 识别与解析
- **I3**：日期闸关着时（集号越出 1..30、或没有发布时间）先问 Mikan-hash 桥。桥有独立上限，超时就退回名字投票。生产 132 个 hash 实测 0 个桥结果出错。
- **I9**：单集条目（特典/OVA）收到第 N 集时，这个名字弃权，不退而取排名更低的候选（那等于替用户再猜一次）。
- **I11**：`[组] 番名-05` 这类无空格写法能洗掉集号尾巴，`某番 - EP12 END` 也不再洗成 `某番-`。生产 3667 条标题回放，0 变化。
- **I10**：用户真改过的集号打标 `episode_manual`，集号展开/回折跳过这类行。空确认不打标。

### 2.3 下载与去重
- **D4**：放行前按番此刻的订阅、锁定源、关键词复核。有意越过锁定的三个入口显式豁免，并有走真实交付链的用例钉住。
- **D7b**：整机断网期间退避用满不转失败。
- **D8**：补齐判"已下过"改用 dedup_key。
- **I6**：修正版判据改为 `_replaceable`，取代 r38 的 `_same_variant`（r38 报告 2.3 节的描述因此已过时）。
- **I8**：提权。
- **F21**：修正版交付在两次 await 之间按主键重读，用户中途排除或删集都不会被改回。

### 2.4 巡检与告警
- **A6**：巡检口径不计"占槽别季行"。被占槽的缺集单独说明"补齐也下不了，先处理绑定"（E-77 待拍板；10-30 已实施 C，出路改成标为『不属于本季』）。
- **A8**：末尾缺口从最大集号的实际发布日起算。
- **A9 / F7**：断更豁免改成"终集按周更已播出且集数收齐"，和判下齐同一个模型。
- **A11**：『源抓取失败』出现新的失败源时再推一次。
- **A12 (3)**：熔断期间状态型事件不再每 30 秒计一次"没送到"。
- **A13**：RSS 断档的 seen 等本组入库后再推进。

### 2.5 qB 与搬迁
- **Q2 / U7a**：文件本就在当前目录的行，搬迁时一律不碰。生产回放 #2 的"搬回来"会误清 10 集，已修。提示只指向实际被清的那几集所在目录，并写明"等新目录下完再删、只删这几集"。

## 六、本轮过程中的一次误操作（如实记录）

解析组的一个**设计** agent 第一次跑测试时多加了一个 pytest 插件参数，`config` 先于测试隔离夹具导入，于是：
- 读写的是你本地的开发库 `data/autorss.db`：修改时间变成 10-29 21:12:54，可能按默认值补写了缺失的设置键；
- 按开发库里的 `DB_BACKEND=mysql` 连了 `10.0.10.20/test_autorrs` 做探活，可能跑过一次 `upgrade_data_schema`。当时的迁移最新版本仍是 `f3c8a1d6b2e9`，开发库本来就在这一版，所以大概率是空跑；
- 测试夹具的"一次性库"守卫在删除数据之前拦下了，**没有删任何数据**。

之后所有 agent 都只用 `-p no:cacheprovider`，开发库修改时间再没变过。建议你有空核对一下开发库的 setting 表和 `test_autorrs`。
