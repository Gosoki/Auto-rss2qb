## 1. 已修的三条 P1

### A1 停机时间被当成「种子没推进」

qB 不可达时 sync 走 `info is None` 分支、**一个字段都不写**；autorss 自己停机时更是一轮都没跑。
两种情况下 `qb_progress_at` 都冻在断档之前，恢复后第一轮 `now - qb_progress_at` 当场超过阈值
（默认 1 天）。后果是**批量**的：关机一天后开机，进程做的第一件事就是把所有在下种子标成 `stalled`
（`core/worker.py` 启动即 `qb_kick.set()`），而 `stalled ∉ TRACKED_STATUSES` ⇒ sync 再也不看它们
（哪怕 qB 已经 3MB/s 在下），`stalled ∈ HAVE_STATUSES` ⇒ 集去重挡着不换源，还推一条内容是错的告警。

修法：判停滞前先问「这段时间我们看得见吗」。新增 `_observation_gap(prev_synced, now)`，
与 `has_active_downloads` 的「新鲜度闸」同源——那条注释写的正是「qB 掉线时 sync 走 None 分支
不刷新 `qb_synced_at`」，**两个消费者共用一个判据，别再分家**。
（这条真实路径此前**全仓零覆盖**：把整条停滞分支废掉，586 条一条不红。）

### A2 `missingFiles` 行被采样到中间态，三道闸同时失效

触发路径是用户按**设计好的修复方式**走出来的：在 qB 里把文件放回去 → 强制重新校验 →
点『立刻刷新』。qB 此刻回的正是 `checkingUP`。而三处闸都在比字面量 `"missingFiles"`：

- 补查名单（`qb_state == "missingFiles"`）→ 覆写后不再包含它
- 而 `checkingUP` 带 `X`（落定）→ 同时掉出 in-flight
- ⇒ **再没有任何路径问过 qB 它怎么样了**

后果分两支：校验成功 → UI 永久停在『校验中』；校验失败/文件仍缺 → 那条『文件缺失』告警
**永不再出现**，而行仍是 `sent ∈ HAVE_STATUSES`，集去重认定盘上有一份 ⇒ 既不重下也不报警。
更糟的是同一次覆写还解除了另外两道兄弟闸：归档闸（归档＝从 qB 移除种子，**恰恰端掉唯一的修复入口**）
与 `qb_summary` 的"已完成"计数（盘上没文件的那一集在仪表盘上算已完成）。

修法：`checkingUP` 从 `SX` 改成 `ST`（**「校验中」不是「不用再看了」**），三处字面量收成一个
共用集合 `_QB_NEEDS_RECHECK`。顺带把 `tests/test_status_tables.py` 那条不变式从
「做种态必然落定」收窄成「**稳定的**做种态必然落定」，并补一条反向断言「短暂态一律不落定」。

### 凭据泄露三条（r12 P2-③④⑤）

`data/autorss.log` 滚动 5 份、`/logs` 页还能整份下载，而本项目三类秘密全内嵌在 URL 里且没有别的配置方式：
- `_safe_host()` 返回 `netloc`，而 **netloc 含 userinfo** —— 推送的 basic-auth 口令随任何一次失败落盘。
  （`core/ssrf.py` 用的是 `httpx.URL.netloc`，那个不含 userinfo，所以那边抄对了；这里抄的是 `urlsplit` 的。）
- 异常串本身带完整 URL：我们自造的消息以 `{url}` 结尾，httpx 抛的 `HTTPStatusError` 也带，
  而 `core/worker.py` 那行 `log.error("抓取失败 %s: %s", name, e)` **连截断都没有** ——
  Mikan『我的番组』随便一次 403 就把 `?token=…` 整条落盘。加了 `safe_url()` / `redact()`。
- 回调 token 未 URL 编码（`openssl rand -base64` 带 `+` 是最现实的情形）。

端到端起真日志验过：三类密钥都不再落盘。
过程中一度以为发现第四条（httpx 每次请求按 INFO 记完整 URL），**查下来是假警报**——
`core/logsetup.py` 早把 httpx 压到 WARNING 了，注释写的正是这个理由；是我的测试脚本
用了 `basicConfig` 而非应用自己的 `setup_logging`。
