### P0 — 两条是我第 1 轮自己引入的回归

| id | 问题 | 为什么危险 | 修法 |
|---|---|---|---|
| `ENG-1` **回归** | 第 1 轮加的"批量缺席闸"**没有出口**：`≥3` 条在下种子且过半从 qB 消失时整轮 `return 0`。判据只看**本轮**比例，于是"用户在 qB 里一次性删掉大半在下的种子"这种**稳态**缺席会每一轮都命中，**永远** return | 缺席行永不落定 → 恒满足 in-flight → 同步循环永不休眠、归档永不发生；连**在场的健康行**也被连坐，进度冻在最后一次同步的值（UI 上是一个不动的「下载中 42%」）。与 `sync_qb_status` 自己两处注释承诺的「保证有限轮内落定」直接矛盾 | 改成**只抑制"判失败"、不跳过整轮**：照常进循环（在场的镜像进度、缺席的打记号），只在落 error 那一步多给一段**有界**宽限 `max(1800, QB_SYNC_INTERVAL×20)`。有界 = 批量抑制自己也会到点 |
| `CAND-1` **回归** | 第 1 轮把选集改成"逐条试到成功为止"，但 `download_anime_torrent` 把**三种失败揉成一个 `False`** | ① qB 抖动时同集第二个 hash 也被发出去 —— 两份可能都进了 qB，其中一条还留在 pending、UI 上永远看不见；② 共因失败（下载目录配错/磁盘满）一次把该集**全部**候选烧成 error，而 flush 只挑 pending → 这一集从此再不会被自动放行，且没有任何提示。**比不修之前更糟** | `download_anime_torrent` 改**三态**：`True` / `False`（这一条自己的毛病）/ `None`（系统性：qB 连不上、保存路径算不出来）。两个批量入口收到 `None` 当场收手；并补上 flush 同款的 `qb.reachable()` 预检 |
| `NG-1`（非回归，既存） | 建表/迁移失败 → `config.load_from_db()` 与 `init_db()` 在同一个 try 里一起没跑成 → 内存里全是硬编码默认值，而 `WEB_ALLOW_CIDRS` 的默认值是空串 = **放行一切** | 一条本该更安全的失败路径，反而把无鉴权、存着 qB 明文密码、能让 qB 往任意目录下载的面板对整个局域网敞开；页面只说"数据库停摆"，一个字不提白名单已失效；且 `load_from_db` 全仓只有 1 个调用方，库修好也不会重读 | 加 `config.loaded_from_db` 标志；netguard 在标志为假时兑现自己 docstring 声明的 fail-closed（只放行回环，本机仍进得去修）；`run_db_watch` 恢复分支补跑 `load_from_db()` |

### P1 / P2

| id | 问题 | 修法 |
|---|---|---|
| `ENG-2` | 第 1 轮加的"已落定则跳过"守卫**两头都错**：`not t.qb_state` 漏掉了绝大多数已完成的行（正常下完会被写上 `uploading`/`stalledUP`），却**误吃**了 `settle_sent` 写的 `("sent",1.0,"",None)` 行 | 判据改成 `qb_synced_at is not None and (not qb_state or qb_state in _QB_SEEDING)`：前半保证 settle 行仍能被回调补上完成时刻（否则永不归档），后半保证做种态不被抹空 |
| `R1` | `deploy.sh` 的 `UMask=0077` 会把 engine 预建的下载目录中间层变成 0700 —— 而 qB 常是**另一个用户**（debian 包/Docker/群晖），连目录都进不去，**种子恒 0% 且无任何报错** | 删掉 `UMask`（`data/` 的权限已由 `config.py` 的 `chmod 0700` 单独收，不牵连下载目录） |
| `R2` | `deploy.sh` 新增的 `LAN_HINT` 那行在 `set -euo pipefail` 下会**掐死脚本**（`grep -v` 无匹配退出 1） | 补 `|| true`；`hostname -I` 同。后果本是"服务已起在 0.0.0.0，用户却既看不到地址也收不到无鉴权警告" |
| `N4` | **手动页「上传 .torrent 文件」整条入口是坏的**：用的是旧版 API `e.content.read()`/`e.name`，而 NiceGUI 3.16 的 `UploadEventArguments` 是 slots dataclass、只有 `sender/client/file` → 必抛 `AttributeError` | 改用 `e.file.name` / `await e.file.read()`；顺带用白送的 `e.file.size()` 加了服务端大小闸。已用真实的 `SmallFileUpload` 走通 |
| `QB-1` | 仍在发 qB 4.x 的 `paused` 参数，而 5.0+ 改名 `stopped` 且**无别名** | 两个都发（老版忽略未知的 stopped，新版忽略未知的 paused）。漏了它，用户开 `AddTorrentStopped` 时种子以 `stoppedDL` 入库 → W 档不计停滞 → 永久 in-flight、永不下完也不报错 |
| `QB-3` | qB 登录失败无负缓存：两条后台线各每 30s 要一次会话，改密/重启后约 75 秒就凑够 qB 默认的 5 次失败、把自己封 1 小时 | 加 `_fail_until`：凭据类失败退避 300s、网络类 30s；设置页保存 qB 配置时调 `reset_cooldown()` 立即解除（冷却是为了别撞封禁计数，不是惩罚用户的显式操作） |
| `QB-2` | qB 5.2+ 的 409（该 hash 已在 qB）被记成 ERROR，与紧邻注释矛盾 | 判据改 `status_code in (200, 409)` |
| `A5` | 源组的 `title_filter` 是**大小写敏感**的裸 `in`，而单番的 `pref_keyword` 用的是大小写不敏感的 `_kw_match` —— 两处口径相反 | 把判据提到 `sources/parse.kw_match` 当唯一真源，三处共用。此前用户填 `1080p` 而该组标题写 `1080P`，那个源组每轮全灭、日志只有一行「0 条」，而设置页对 `pref_keyword` 的示例文案用的恰恰是小写 |
| `PIN-2` | 钉 IP 时重写的 Host 头丢掉端口 | 用 `request.url.netloc` 而非 `.host`。此前非默认端口的私站取种恒失败，而浏览器/curl 正常，排查方向被完全带偏 |
| `A1` | `alembic/env.py` 的 `include_object` 不排除另一 role 的版本表 | 排除 `alembic_version*` 与 `*_inflight` partial index。此前按 `db/schema.py` 文档化的流程跑 autogenerate 会生成 `drop_table('alembic_version_meta')`，应用后第二次启动变永久 fatal |
| `C2` + 上轮 `migrate-hot-source-db` | 迁移的目标可以正是**当前在用**的业务库，且迁移在线程里跑而后台采集仍在写同一个库 | 迁移期间拿住 `worker._poll_lock` 与 `_scan_lock`；目标是活库时在确认框里明说 |
| `C6` | 停摆闸放在了最长 2 小时休眠**之前** | 挪到 `qb_kick.clear()` 之后 —— 用两小时前的结论决定现在做不做，等于没判 |
| `R3` `R4` `R5` | 三条 UI 回归：`:focus-visible` 的 `border-radius:4px` 把圆形图标按钮压成圆角方块；『跳转到』只有 `:hover` 仍键盘够不着；剧场版详情徽标文案统一了颜色没统一 | 分别删 `border-radius`、补 `:focus-within`、补 `color=blue` |

## 2. 需要你拍板的（本轮新增）

| # | 问题 | 我的选择与理由 |
|---|---|---|
| **Q1** | 批量缺席闸的出口形态 | **已按"进循环 + 记号 + 有界抑制"实现**。这是 P0 回归，留着不修的代价高于等你确认；另两个候选（计数器强制放行 / 只看新增缺席比例）分别只修一半症状、或在"用户一次性删光"时判据恒假等于没闸。**若你要改口径，改这里即可**：`core/engine.py` 的 `batch_absent` 与 `grace` 两处 |
| **Q2** | 三态里"系统性失败"的边界 | **已按 B 实现**：`add_to_qb → None`（qB 连不上）+ `build_save_path is None`（越界/无处下载）。**不含**取种阶段的连接类异常——那会把源站单条 404/502 误判成系统性，正好废掉"逐条试到成功"的初衷 |
| **Q3** | `missingFiles` 行的出口 | 推荐 A：给 sync 加一条"`qb_state='missingFiles'` 的行每轮也拉一次"的补查，qB 侧修好后被真实态自动覆写、告警自动消失。B（UI 加"我已修好"按钮）要求用户理解一个内部状态才知道该点什么 |
| **Q4** | flush / 标注 / 补下 三条挑选口径要不要统一 | 本轮**只改了注释**。要统一得同时给 `_PLAN_COLS` 补 `retry_count` **并且**让 flush 也用 `prefer_fresh`——那会改变后台自动下载的挑选行为（失败过的候选永久降权），值得单独一次带用例的改动。**只做一半是明确的回归** |
| **Q5** | SSRF 守卫覆盖到哪 | 推荐 B：代理分支保留字面 IP 判定；feed 路径**只对重定向后的跳**强制内网判定，首跳（用户自填地址）放行。首跳强制会直接打断"自建局域网镜像"这一合理用法 |
| **Q6** | qB 认证 | 本轮做了 A（补 `stopped` 参数 + 登录负缓存）。B（支持 qB ≥5.2 的 API Key，天然不会被失败登录封禁）要在设置页加一组字段并处理新旧 qB 分支，下轮 |
| **Q7** | 备份的边界 | 推荐 B：业务库是 SQLite 时（绝大多数用户）连业务数据一并备；是 MySQL 时明确告知"只备了配置"。**必须用 `VACUUM INTO` 而不是 `shutil.copy2`**——WAL 库直接拷主文件会拿到陈旧甚至空库，而备份的失败方式恰恰是"天天成功，恢复时才发现" |
| **Q8**（上轮遗留） | MySQL 后端是否降为"实验性" | 四条 MySQL 专项缺陷仍挂着。若你实际只跑 SQLite，在 README 标一句即可整组降 P3 |
