| # | 问题 | 修法 |
|---|---|---|
| 1 | **两个限流桶都在【发送之前】记账**：推送服务抖一下、连着失败 N 条，用户一条没收到，一小时额度却烧光了 | 桶拆成"只查"与"送达后记账"两步（`_rate_ok`/`_rate_commit`、`_state_rate_ok`/`_state_rate_commit`）。用户口径本来就是"每小时**收到**几条"（设置页标签）与"另有 N 条被**限流丢弃**"（消息尾巴） |

## 二、反驳者订正了报告自己的 6 处

这一节比"修了什么"更值得看——**报告犯的正是本项目自己那三种缺陷形状**。

| 原报告说 | 实际是 |
|---|---|
| "保存一次设置，那条『已恢复』就被**永久**吞掉" | 边沿**下一轮会自愈**（DECISIONS D-04 记的就是这条）。真正丢的只有一种：保存恰好落在**故障刚结束的那几秒**。P1 → P2 |
| "模块自己写死的规矩是『记账必须晚于发送』，四处只做了两处" | 那句规矩的字面作用域是**冷却窗口与落库标记**，没提限流桶。桶该按送达计数的依据是**用户口径**（设置页标签 + 消息尾巴），不是那句注释 |
| "一轮 flush 最多放行 **201** 集 × 10 秒 ≈ 33 分钟" | 加上 flush 自己的过滤链（订阅 → `auto_downloadable_ep` → 锁定源 → 关键词 → grace），真库上只有 **11** 个去重集。201 是**去掉订阅过滤**才有的数 |
| "写错 `NOTIFY_URL` 时唯一的诊断说的是『(未配置)』" | 完整日志是 `通知发送失败：UnsupportedProtocol: Request URL is missing an 'http://' or 'https://' protocol.（(未配置)）`——**httpx 原文已经把病因说清了**。真问题是那个括号后缀与同行报错自相矛盾 |
| "恢复第 2 步**必然**毁数据" | 正常关服路径（`systemctl stop` → uvicorn 优雅关闭）下 `-wal` **根本不存在**，那一步通常是空操作。它的问题不是"必然毁"，而是"**唯一不可逆的一步，而且省不掉**" |
| "meta 备份里其实装着业务表，**三处**在说假话" | 是**四处**（还有 `db/backup.py:12-13` 模块 docstring） |
| "剧场版失败/停滞告警" 的引用坐标 `core/movies.py:812-816 list_failed` | 项目里没有 `list_failed` 这个名字；正确的是 **`core/movies.py:826 failed_rows()`** |
| "feedparser 对纯 HTML 页 `bozo=False`" | **原报告不成立，但我第一次的订正也不够准**（R18 复测）。真实的 HTML 错误页/拦截页（未自闭合 meta、裸 `&`、`&nbsp;`）全都是 `bozo=1`，旧告警对它们是响的；真正静默的是**良构的** XML/XHTML（最简 XHTML 页、XML 维护页）与空 body。判据是【良构与否】，不是【是不是 HTML】 |

最后一条是我自己复测出来的：如果照着原报告的premise改，会写出一条针对不存在的现象的用例。
**审计报告本身也要当成待验证的输入。**

## 三、修复过程中我自己踩的两个坑（都被套件抓住）

1. **新写的用例直接给 `config` 模块赋属性**（`config.NOTIFY_MAX_PER_HOUR = 2`）。
   config 的读取走模块级 `__getattr__ → _v`，赋属性会**永久遮蔽**这条路径，
   函数末尾改回去也没用——后面所有用例的 `cfg(...)` 静默失效。
   表现是一条**毫不相干**的用例开始失败。改配置一律走 `cfg` 夹具，这句已写进用例注释。

2. **`reset_state()` 同时承担了"生产语义"和"测试夹具"两种职责**。
   把生产那半收窄之后，9 条用例当场变红——它们靠它拿干净的进程状态。
   正解是夹具自己清模块字典（`tests/test_notify_events.py::_fresh`），
   而不是把两种语义继续压在同一个函数上。
