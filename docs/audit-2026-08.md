## 2. 主系统与插件的关系：现状与裁决

### 2.1 现状事实（已逐处核实，非推测）

`sources/base.py` 的 docstring 说「新增一个源只需继承 `Source`、实现 `async fetch()`」——**这句话已经不成立**。今天加第三个源（如 dmhy）实际要动 6 处：

| # | 位置 | 漏改的后果 |
|---|---|---|
| 1 | 新建 `sources/dmhy.py`（约 120 行，其中 **~40 行是从 nyaa/mikan 逐字抄来的主系统策略**：`clip_title`/40hex 校验/`is_batch`/`title_filter`/`parse_title`/多括号兜底/`subgroups`/`quarter_of`/12 字段构造） | — |
| 2 | `core/worker.py` `build_sources()` 的 if/elif | 每轮静默跳过（**有**日志） |
| 3 | `core/anime.py` 补齐逻辑里第二条 if/elif + 模块级 `*_search_url()` | 详情页「补齐」**静默返回 0 条、无日志** |
| 4 | `pages/sources.py` 的 `SITE_OPTS` | UI 下拉建不出该源组 |
| 5 | `core/engine.py` 的 `_SITE_TZ` | **不报错，发布时间整天错**（该文件的注释亲口描述过这个历史故障） |
| 6 | `config.py`（可选）站点根地址/镜像/默认 feed | — |

外部改动合计 **< 10 行、5 个文件、零 DB 迁移**（`sourcegroup.site` 是无约束 TEXT）。第 5 处是唯一「漏了不报错」的。

另外三条已核实的事实：

- `sources/nyaa.py` / `mikan.py` 的 `site` **类属性是死代码**——全仓无人读实例的 `.site`，真正生效的是构造 `ParsedItem` 时手抄的字面量。
- `ParsedItem` 12 个字段里只有 4 个是真·源特有事实；`episode_abs` / `search_names` 主系统后来各重算了一遍。
- Mikan 扮演 **4 个角色**（RSS 源 / 搜索端点 / 剧场版 catalog / bgm 识别兜底桥），**只有第 1 个走 `Source` 契约**。

### 2.2 裁决：**不做注册表，做 `RssSource` 去重**（推荐，待你拍板 → §5 Q1）

数据说话：源层最近 12 次提交里 **8 次是「同一改动改两遍」**（nyaa 和 mikan 的 `_parse` 95% 重复且已漂移），而 `site` 分派一个月只改过 1 次。

> **这个项目在流血的不是「加源要改 5 处」（一共 10 行，一个月一次），而是「同一段解析逻辑存了两份且已经漂移」。注册表治不了后者，去重能。**
> 而且本项目在 `core/engine.py` 已经为「同一份知识记两处会漂移」立过规矩（qB 状态词表统一到一张表）——**sources 层是这条纪律唯一的例外区**。

| 维度 | A 注册表（装饰器+CAPS） | B 完整插件契约（能力协议 + schema 驱动 UI） | **C+ 去重（推荐）** |
|---|---|---|---|
| 改动文件数 | 6 | 8~10（含 2~3 新模块） | **3** |
| 净行数 | +40~+80 | +400~+600 | **−40~−60** |
| Alembic 迁移 | 否 | **是**（加 `config_json` + 数据回填，两方言都要过） | 否 |
| 回滚代价 | 改回 if/elif | **删库重建**（本项目明确不支持 downgrade） | `git revert` |
| 消除 `_parse` 95% 重复 | ❌ | ✅（顺带） | **✅（核心目标）** |
| 消除 `_SITE_TZ` 漏改 | ✅ | ✅ | ✅ |
| 典型失效模式 | 导入时序 → 少一个站（有日志） | 迁移漏判 → **某源静默拉 0 条**（无日志、0 测试兜底） | 判据顺序搞错 → 少收条目（`/parse` 页可手验） |
| 对齐实测变更频率 | 分派 1 次/月 → 收益低 | 同左，成本 ×8 | 解析 12 次/月（8 次改两遍）→ 收益高 |

**C+ 的具体形态**（约 −50 行）：

```python
# sources/base.py
class RssSource(Source):
    site: str = ""
    TZ = timezone.utc                     # 从 core/engine.py 的 _SITE_TZ 搬进来
    def _hash_of(self, entry) -> str: ...    # 子类唯一覆写点 ①
    def _url_of(self, entry) -> str: ...     # 子类唯一覆写点 ②
    async def fetch(self): ...               # 现两份完全相同，合一（顺带补 mikan 缺的 feed.bozo 告警）
    def _parse(self, entry): ...             # 现两份的公共 ~40 行，合一
# sources/__init__.py —— 显式字典，不用装饰器（无导入时序风险，读一眼就知道全集）
SOURCES: dict[str, type[RssSource]] = {"nyaa": NyaaSource, "mikan": MikanSource}
```

`SOURCES` 让 `worker.build_sources` / `anime` 补齐 / `pages/sources.py` 的 `SITE_OPTS` / `engine.torrent_time` **四处硬分派全部塌成查表**，`_SITE_TZ` 整个删掉（TZ 变成类属性）——唯一那处「漏改不报错」的知识被收回源自己身上。

**如果只做一件事**：合并两份 `_parse` 并把 `_SITE_TZ` 挪成类属性。零 DB / 零 UI / 零迁移，`git revert` 即可回滚，且是将来真上注册表时的前置步骤，不会白做。
