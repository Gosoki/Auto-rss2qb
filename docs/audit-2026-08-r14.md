### 徽标：一句"统一字号"从写下那天起就没生效过

`.q-badge{font-size:14px}` 写在 `@layer overrides{}` 里，而 **Quasar 的 CSS 完全不在任何 `@layer` 内**（实测 `grep @layer` = 0）。
按层叠层规范，**普通声明是「无层级 > 有层级」**——它压不过 Quasar 无层级的 `.q-badge{font-size:12px;line-height:1}`。

同一块里的背景色规则之所以生效，是因为它们**都带 `!important`**（important 声明的次序反过来）。字号那条漏了。

真实状态因而是：带 Tailwind `text-sm` 的 31 个是 14px（Tailwind 也无层级），其余 40 个仍是 12px。
**而"把 text-sm 从调用点剥掉"这个看似正确的清理，如果不同时补 `!important`，会让全站徽标退回 12px——比改之前更糟。**

修法：全局规则补齐四条并带 `!important`：`font-size` + `line-height:1.45` + `inline-flex` + `align-items:center`。
最后一条把"字在框里居中"从**靠字体度量碰运气**变成**布局保证**——Quasar 原样式没有 display 规则、
靠 `vertical-align:baseline` 定位，而中日文字形的 ascent+descent 超过 1em，`line-height:1` 时字会偏低。

> ⚠ 以上是 CSS 规范层面的推导。本环境没有浏览器，**像素未实测**，需人工过目确认。

这是本轮最值得记的一课。并发维度提出 10 条发现，其中三条带着看起来很硬的实测数字：

| 报告的断言 | 反驳者的实测 |

## 五、结论：双引擎设计是不是最优解

**是，不建议换。** 它要解的鸡生蛋问题是真的：连接参数得存在某个库里，一起搬去 MySQL 就再没有自救入口。
两个替代方案代价都更大：

· setting 也搬去 MySQL + `.env` 存连接参数 → 把"改数据库"从网页操作降级成"ssh 改文件 + 重启"，
  与本项目"无鉴权、单机、网页配置"的定位冲突；且 75 个 setting 键里有 60 多个与连接无关。
· 只支持 SQLite → 砍掉"多机共享一份库"这个真需求。

**最脆的三个点**（见上文 4.3 及反驳者更正）：迁移期的写路径作用域、
一次性回填闩存在 meta 却描述 data 内容、MariaDB 判据有两套（`is_mysql` vs 手写 `dialect.name`）。

## ⚠ 更正 r14 的一个错误判断：徽标的层叠前提

r14 写着「Quasar 的 CSS 完全不在任何 `@layer` 内（实测 grep @layer 为 0）」，据此断言
「徽标字号统一从写下那天起就没成立过」。**这是错的。**
NiceGUI 的 `templates/index.html` 第 13 行声明了层序，Quasar 是通过
`@import ... layer(quasar)` 进层的——**层写在 @import 那一侧**，grep 它的 CSS 文件内容看不到。

```
@layer theme, base, quasar, nicegui, components, utilities, overrides, quasar_importants;
```

`overrides` 在 `quasar` 之后 → 项目原来那句不带 `!important` 的 `font-size:14px` **一直是生效的**。

`!important` 仍该留，但**理由完全不同**：要挡的是 **Tailwind**——它由 `tailwindcss.min.js`
运行时注入、**不属于任何层**，而无层级的普通声明压过所有有层级的。注释与用例断言消息都已按事实重写。
