# 第 4 轮审计报告（2026-08-19）

> 方法：16 个 agent。四位**回归审查员**逐条追问本轮新功能（三件套）；5 个方向审计剩余区域，
> 各配 1 个强反驳者。53 条发现，43 条通过对抗验证。
>
> 本轮顺序同第 3 轮：先落地、再让工作流审刚写完的代码。

## 0. 结论：三件套引入了回归，**355 个用例一条都没抓到**

审计把 20 条发现归成了**两条结构性根因**，其余都是它们的投影 —— 这个归纳比清单本身更有价值：

1. **瞬时判据喂了永久标记。** `episode_coverage` 是随种子状态浮动的瞬时量，`finished_at` 却只增不减。
   二者相接 = 一次误判永不撤销。
2. **所有「已通知/已处理」的记账都早于「消息确实出门」。** 冷却、状态边沿、两个落库标记，
   四处一律先记账后发送 —— 被限流或未订阅而丢弃的告警**永久丢失**，
   包括 `qb_down` / `db_down` 这两个全项目唯一的带外故障信号。

另有一条与三件套无关、但更危险的独立缺陷（见 P0-1）。

## 1. 已修（本轮落地）

### P0

| id | 问题 | 为什么危险 | 修法 |
|---|---|---|---|
| `CFG-SAVE-DEFAULTS` | 配置没从库读出来时（建表/迁移失败），设置页显示的全是**硬编码默认值**；此时按保存会把库里全部已有配置改写成默认 | `WEB_ALLOW_CIDRS` 被清空 = 无鉴权、存着 qB 密码的面板重新对整个局域网敞开；`NOTIFY_URL` 的推送密钥被抹掉。**全程零报错，还弹一句绿色的「已保存」** | `_save` 开头拦下并说明原因；页面顶部挂 warn_banner 说明「现在显示的是默认值」 |
| `NOTIFY-ACCT` | 记账早于发送：`event()` 先写冷却再判限流、`state()` 先写状态记忆再发 | 一条被限流吞掉的 `qb_down` 把状态记成「坏」，此后每轮都判为「没翻转」而静默返回 —— 用户最后只收到一条孤零零的「已恢复」。被丢弃的 `failed` 还白烧 6 小时冷却 | `event()` 改为**返回是否真的发出去**；冷却与状态记忆都只在 True 时落位 |
| `FIN-LATCH` | `finished_at` 单向锁存 × `episode_coverage` 瞬时判据 | 一次误判永久：停订开着时该番**永久停订**（flush/补下全返回 0），关着时也**永久退出断更巡检**，用户不点按钮就永远好不了 | `sweep_finished` 改「补 + **撤**」：每轮对已标记的番重算，不再集齐就清掉标记（`finish_optout` 的两个方向都不碰）。整个功能从一次性事件变成幂等的状态同步 |

### P1 / P2

| id | 问题 | 修法 |
|---|---|---|
| `ENRICH-REFUND` **（我第 4 轮那条修复本身写错了）** | 我加的「bgm 不可达就退款」判据是「一部都没命中」—— 而**候选池里常驻的恰恰是 bgm 搜不到的番**，「没命中」是稳态不是故障。等于把退避阶梯整个废掉：`enrich_tries` 永远回到 0，每个节拍重打一遍 bgm，`REENRICH_MAX_TRIES` 永不兑现 | 判据改成「一部都**没问成**」：`services/enrich` 新增连接层失败计数，逐部取调用前后差值，只有每一部都是连接层失败才退款 |
| `CFG-WATCH-DEAD` **（我第 2 轮那条修复不可达）** | 我把「库回来了补读配置」写在 `was_down and not now_down` 的边沿里，而建表失败走的是 `mark_data_fatal`，此后探测恒返回 fatal、边沿永不成立 —— 它本来要防的「进程到死都用着默认配置」照旧发生 | 移出边沿：配置库恒是本地 SQLite，本就不必等业务库回来，每轮试一次即可 |
| `SUB-PLAN` | `subscribed_where()` 漏收 3 处标注侧 | 三处收口；仪表盘拆桶新增**「已完结」一档** —— 否则它们会掉进「备用项」，而那张卡的说明是「同集已有更优版本」，纯属误导 |
| `MERGE-OPTOUT` | `_merge_anime` 没迁 `finish_optout`/`finished_at`（而那份清单的注释明写「以后再加同类字段务必同步加到这里」） | `finish_optout` 取并集（那是用户的显式意志）；`finished_at` 清空让巡检重算 |
| `IDLE-OPTOUT` `IDLE-SCOPE` | 点完「继续订阅」立刻收到断更提醒且永久复发；断更正文取的是最老 3 部（全是两年前的老番），真正刚出事那部只贡献计数 | 候选排除 `finish_optout`；`resubscribe` 一并推 `idle_notified_at`；**加活跃度上界**（4 倍阈值，超出视为「早就完了」）；正文按静默时长排序 |
| `NOTIFY-MARK` | `idle_notified_at` 先落库后发通知 | 没发出去就不记账 —— 这个提醒本身就是靠它去重的，丢了补不回来 |
| `FIN-BULK` | 老库首次巡检会把历史上早已完结的番一次性全判，几十条推送把限流额度占满、把真正的新事件挤掉 | 首轮判为回填：只打标记不推送 |
| `MOVIE-NOTIFY` | 剧场版交付仍走裸 `notify()`，绕过订阅过滤与限流 | 改走事件层。此前设置页那句「留空＝一条都不发」对剧场版是假的，批量下 30 个版本 = 30 条不可关的推送 |
| `QB-DOWN-SCOPE` | `qb_down` 只在采集轮评估，而全新库采集默认关 → **开箱恒不触发** | 抽 `qb_precheck()` 三处共用；并挂进 qB 同步循环（唯一一条与采集开关无关又必然要碰 qB 的路径） |
| `SWEEP-TRY` | 三段共用一个 try（`sweep_finished` 一抛，断更与积压告警整轮不跑）；库停摆后要再等 3 小时；间隔填 0 变成每 60 秒全表扫描 | 三段各自 try；停摆改 30 秒重试；输入框加下限 |
| `BACKLOG-*` | `NOTIFY_EVENTS` 默认值漏了 `backlog`；「待识别已清空」在还剩 4 部时就发出（阈值下穿≠清零） | 补默认值；ok 文案随实际条数生成 |
| `MODEL-COMMENT` `UI-COPY` `FIN-RECONFIRM` | 三处注释/文案与实现不符 | 改成事实 |

### 采纳的拍板项（Q1/Q3/Q4/Q5）

| # | 决定 | 理由 |
|---|---|---|
| **Q1(b)** | 完结判据收紧到 `qb_progress >= 1.0` | `sent` 只表示「已交给 qB」，`downloading`/`stalled` 更是明摆着没下完。`qb_progress >= 1.0` 是本项目**已有**的「真下完」信号（归档条件用的就是它），关跟踪时 `settle_sent` 也会写 1.0 —— 不是新发明的口径，不构成「同一判据两处手抄」 |
| **Q3(a)** | 状态型事件不占 `NOTIFY_MAX_PER_HOUR` 的桶 | 每次翻转最多两条，频次天然有上界。共用一个桶时桶满会把边沿推迟到下一轮，而 `qb_down` 的下一轮可能是 20 分钟后 |
| **Q4(b)** | 断更巡检加 4 倍阈值的活跃度上界 | 不依赖季度字段填得对不对，语义也更直白：「断更」是最近才安静下来的，不是两年没动静的 |
| **Q5** | list 型配置的「新增成员并入」 | **这条比它看起来重要**：`load_from_db` 只补缺失的键，所以将来往 `EVENTS` 加的任何新事件，对所有已存过一次 `NOTIFY_EVENTS` 的库都是**静默默认关** —— 会挡住后续所有「加一类提醒」的改进。用「上次见过哪些事件」的快照做差集，用户显式取消过的不会被并回来 |

## 3. 完结检测的判据风险（专节）

这是本轮唯一会**静默改变下载行为**的功能，所以单列。

**误判成完结的路径与现状：**

| 路径 | 现状 |
|---|---|
| bgm 的 `total_episodes` 少记一集 | **仍存在**，无法从我们这边判断。这是 `ANIME_FINISH_UNSUB` 默认关的主要理由 |
| 「已交给 qB」被当成「下完了」 | **已关闭**（Q1(b)：判据要求 `qb_progress >= 1.0`） |
| 停滞/在下的种子被算作到手 | **已关闭**（同上） |
| 小数集 / 特别篇灌水 | **已关闭**（只数 1..T 的整数集号） |
| 歧义段番的 coverage 是假的 | **已关闭**（一律不判） |
| 一次误判永久生效 | **已关闭**（每轮重算并撤销） |

**默认关是对的，但「先观察一阵」需要看得见的东西**：详情页有 `🎊 已完结` 徽标（tooltip 会说明当前这台机器上它意味着什么）、
仪表盘有「已完结」一档、通知里有 `finished` 事件。开关打开前建议先看这三处标得对不对。

**判错了用户能看出来吗**：能。停订后新集照常入库（只是不自动下），详情页会显示待下的种子；
点「继续订阅」即可恢复，且此后不再自动判它完结。
