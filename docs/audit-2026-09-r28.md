## 一、SSRF 守卫放行了整段 CGNAT / Tailscale —— **一次 Python 升级引入的静默回归**（P1）

`core/ssrf.ip_is_internal` 的判据是 `ipaddress` 的
`is_private / is_loopback / is_link_local / is_reserved / is_multicast / is_unspecified`。
而 CPython **gh-113171（3.12.4 起）** 把 `100.64.0.0/10`（RFC 6598 共享地址段）的
`is_private` 从 True 改成了 **False**。本机实测（Python 3.12.13）：

```
100.64.0.1        is_private=False  is_global=False  is_reserved=False
```

**仓库里一行代码都没动过**，这一整段就从判据里掉了出去。而它恰恰是最该防的一段：
Tailscale 给每个节点分的就是这里，CGNAT 家宽同理，本机到那些地址是通的。
被投毒的 feed（或 302 跳转）只要给出
`http://100.64.x.y:8080/api/v2/torrents/delete?hashes=all`，
常驻的采集/交付协程就会替它发出这个可控 GET —— 而这正是本模块 docstring 自己举的例子。
取种是**最严格**的那条路径（每一跳都判），`guard_redirect_request` 的重定向跳同样放行。

### 修法：并集，不是换一套

```python
if ip.version == 4 and ip in _SHARED_V4:      # 显式的 100.64.0.0/10
    return True
return (ip.is_private or ... or not ip.is_global)   # 再并上"不可路由到公网"
```

**不能拿 `not is_global` 去替换原来那串**：组播 `224.0.0.1` 的 `is_global` 是 **True**（实测），
换过去等于把组播放行；NAT64 的 `64:ff9b::/96` 同理会从"拒"变成"放"。并集只会更严。

另加一条**前提断言**用例：它不测我们的代码，测的是 CPython 的语义
（`100.64.0.1` 的 `is_private` 必须是 False、`224.0.0.1` 的 `is_global` 必须是 True）。
哪天上游又改口径，它会红一次提醒人来复核 —— 而不是等下一次审计。

变异：回到 R26 的判据 → 当场变红（两条机制互为冗余，各删一半仍绿，这是有意的，
用例钉的是**行为**不是实现，理由写在 docstring 里）。

## 二、四位集号的合集包被当成单集下载（P1）

标题 `番名 - 1156-1170`（四位连续集合集包，长番常见）**实测**：

```
is_batch=False   extract_episode=1156
```

两道判据同时失效：
- `_EP_END` 的负向前瞻还是 `\d{1,3}`，对 `1170` 恒不成立 → `-` 被当成合法分隔符 → 抽出 1156；
- `is_batch` 的裸区间那条要求"抽不出集号"，而集号刚被抽出来了；
  何况 `_BARE_RANGE_RE` 两侧也还是 `\d{2,3}`，四位一侧本来就匹配不上。

后果：一个十几集/几十 GB 的合集包以「第 1156 集」入库，`auto_downloadable_ep(1156)=True`
→ 被当单集下回来；同时占住去重键 `(anime_id, 1156)`，真正的第 1156 集来时被写成 `skipped`，
而 `info_hash` 已被占死、**不可逆**。

三位区间不会这样（`- 118-119` 抽不出集号 → 判成合集）—— 这是**放宽了抽取侧、守卫侧没跟上**，
与 `_BATCH_RE` 的 EP 条踩的是同一个坑（那条已经放宽过一次，这两条漏了）。

修法：`_BARE_RANGE_RE` 与 `_EP_END` 的前瞻一起放到 4 位。
**真库 2218 条标题逐条比对，改前改后一致率 100%**（零误伤）。

新增一条**结构守卫**：从各条正则源码里抠出 `\d{a,b}` 的上界比大小，
断言 `_BARE_RANGE_RE` / `_BATCH_RE` / `_EP_END` 的位数上界 **≥** `_EP_PATTERNS` 的。
下次再放宽集号时，忘了同步的那一条当场变红，而不是等某部长番播到第 1000 集。
两条变异（各退回 3 位）全红。

## 三、我试出来又**回退**的一条：全括号标题尾部的圆括号注释

审计报的是：标题形如 `[组][番名][05][1080p]（检索用：XXX）` 时，圆括号不是标签块，
洗完剩下的注释成了番名 —— 风险是同一个组的不同番共用别名键、被并成同一部。

我先按建议改了（判成"没有番名"），然后**拿真库 2218 条标题逐条比对**，发现不能做：

| 写法 | 改动波及 | 里面有什么 |
|---|---|---|
| 剥掉**结尾**的括号组 | **64** 条 | 含官方标题自带括号的番：`我们不可能成为恋人！绝对不行。（※似乎可行？）`、`尼古喵喵(邪竜解放版)` —— 等于改动库里**已有番**的别名键 |
| 判成"没有番名"（收窄版） | **33** 条 | 其中 **20+ 条是 DBD-Raws 的剧场版**，括号里装的是**日文原名**：`(映画小林さんちのメイドラゴンさみしがりやの竜)`、`(きみの色)`、`(名探侦コナン只眼の残像)` |

后者那条路**今天是能用的**：别名键唯一，而 `_clean_for_search` 会把括号剥掉，
搜索词正是正确的日文原名。改成空名之后，按 `_clean_name` 自己的注释
「空番名 = 主流程**静默丢弃整条种子**」，这 20 多部剧场版会直接收不到。

而审计报的那条风险**今天并不成立**（真库 6 个源组的字幕组白名单都填了，
那些组进不来；现有注释文本也各不相同、没有碰撞）。

**已全部回退**（真库比对确认：与改动前逐条一致），记成 **E-51** 等你拍板，
连同真库里那 8 条现场证据（SweetSub 的 `（检索用：纯洁庞克）` 与
`（先行版/有码/检索用：纯洁朋克）`—— 同一部番被两个注释拆成了两个别名键）。

## 四、R27 我加的搜索框，每打一段字焦点就没了（P2）

搜索框建在 `manage_panel`（`@ui.refreshable`）**里面**，而它的 `on_change`
最后一句就是 `manage_panel.refresh()` —— refresh 会 `container.clear()`
把这个输入框一起删掉再新建一个。于是**每打完一段字停顿 300ms（debounce），
焦点和光标就没了**：搜「葬送」停一下想补「的芙莉莲」，后面一个字都打不进去。

修法：把搜索框与命中计数提到 refreshable 之外的稳定容器（`_build_manage_tab`），
计数改成给稳定 label 赋 `.text`（同 `logs.py` 的写法）。

守卫按 **AST** 判「`.mark("anime-search")` 那一句在不在 `manage_panel` 的函数体里」——
焦点丢失在 `testing.User` 里根本观察不到（那一层没有真正的 DOM），只能钉结构。
变异（搬回面板里）变红。

## 五、30 秒定时器把『已忽略』面板整个重建（P2）

面板里每个 `ui.expansion` 都是 `value=(i == 0)` 硬编码重建、没有任何持久化的展开意图
（对比 `manage_page["expand"]`）。于是用户刚展开的折叠块每 30 秒自动收起一次、
滚动位置一起丢 —— 最难受的正是底部那个『已删除的种子』：
它恰恰是用户展开去找条目点『重新下载』的地方，展开 → 找 → 还没点到就合上了。

摘掉那一支不丢任何东西：本页的操作走 `refresh_dynamic()`（那里点名刷了 `reject_panel`），
而后台改动 rejected 的只有『开始使用日超期忽略』那条批量重算 —— 不是 30 秒尺度的实时量。
顺带省掉每 30 秒一次事件循环上的同步查询（真库快照上整页构建 127ms）。

守卫按 AST 数 `_refresh_live` 里出现的 `<panel>.refresh()`，
`reject/confirm/fail/manage` 四个面板一个都不许进来。变异（加回去）变红。

## 六、bgm 绑定的第一次 120 秒往返在防抖之外；剧场版侧三个入口整条都没有（P2）

四个绑定入口都是先 `await require_bind_confirm(...)`，而它**第一句**就是
`enrich.fetch_by_id`（`_RESOLVE_BUDGET` = 120 秒）—— 这一段全在 `busy_action` 之外：
按钮不置 loading、无去重键。bgm 慢或不通时跑满 120 秒，页面零反馈 → 用户再点一次 →
第二个协程各自跑一遍。

剧场版侧更进一步：`_bind` / `_bind_from_input` / `_refail` **三处整条都没有** `busy_action`，
最长约 **240 秒**（两次 120 秒预算）完全没有视觉反馈。连点之后会叠出两个
「绑定到《X》？」确认框，两条协程各自往下走一遍 `bind_movie_bgm` ——
而它末尾的身份守卫 `_merge_movie` 最后一步是 `s.delete(loser)`，**没有撤销入口**。

修法：四处的回显闸一律挪进 `busy_action`，剧场版三处补齐（键 `mov-bind:` / `mov-refail:`，
与番剧侧分开 —— `busy_action` 的键是模块级的）。
守卫按 AST：每一处 `require_bind_confirm(...)` 都必须落在被 `busy_action` 传出去的内层函数里。
两条变异（把回显闸挪回外面）全红。

## 七、设计语言的三处

- **`/parse` 判定横幅同一行两个色号**：图标 `text-{color}-400`、文字 `text-{color}-300`，
  而绿那一档还是 green-400、与全站的绿（token 表与 `.q-badge.bg-green` 都是 green-500）不同色。
  R27 刚为"同一个盒子里两种绿"改过一次 `manual.py` 并立了守卫，这一页原样存在同一个毛病
  —— 因为守卫扫的是**字面**类名，看不见 f-string 拼出来的。
  改成从一张 `_VERDICT_SHADE` 表取，并给守卫补上第三条判据：
  **动态色相 + 写死色号**（`f"text-{color}-400"`）一律不许；
  色号也算出来的那种（`kpi_cards` 的 `f"text-{hi}-{shade}"`，规则是"绿 500 其余 400"）不算。
- **`recent_table` 的原始种子名是全站唯一的 10px**：同一份内容在另外五处全是
  `text-xs(12px)/gray-500`，而这一处写死 `font-size:10px` + gray-400 藏在 Vue 插槽字符串里，
  谁也扫不到。改成 12px + 更弱的灰（`warn_banner` 的注释本来就把"原始种子标题"列在那一档）。
- **`/parse` 的开关被配置闸拦下却不回拨**：全站过这道闸的另外三个处理器都是**按钮**，
  没有可见状态；只有这一处是开关 —— 拦下之后界面显示"开"、config 一点没变、
  下面的判定仍按"关"算，用户会以为解析逻辑坏了。补 `sw.set_value(config.…)`（用真值回填，
  不是取反 —— 取反在重入时会漂），并补一条守卫：
  凡被 `on_value_change` 接上、且过配置闸的处理器，必须出现 `set_value`。
